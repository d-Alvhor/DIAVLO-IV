## 🟡 E5 — Se invierte cuál es el atajo *principal* de Awakened PoE Trade

§0 construye el relato así: Ctrl+C es "el mecanismo", y Ctrl+Alt+C es "una **segunda** combinación".
Para APT concretamente, **la documentación del propio proyecto dice lo contrario**.

`docs/nothing-happens.md`, verbatim:

> "As you may have noticed, compared to other third-party PoE tools APT uses 'Advanced Descriptions' key."

`docs/no-item-mods.md`, verbatim:

> "you need to make PoE copy the item with mods when the `Ctrl + Highlight + C` is pressed"

Es decir: **la copia avanzada es la vía primaria de APT**, no un extra. Ctrl+C a secas es lo que usan
"other third-party PoE tools". El informe no se equivoca sobre que ambas existen, pero sí sobre cuál es
la principal en la herramienta que toma como referencia del sector.

Esto **refuerza** la lección para DIAVLO IV en vez de debilitarla: la herramienta líder eligió la vía que
da tier y afijo anotado, no la que da texto plano. Pero conviene contarlo bien.

## 🟡 E6 — "Ctrl+Alt+C" no es una combinación fija: el modificador es rebindable en el juego

El informe lo trata como constante. La documentación de APT lo trata como variable: la combinación es
`Ctrl + <Highlight> + C`, donde **"Highlight" es una tecla configurable en las opciones de PoE** que por
defecto es Alt. De `docs/no-item-mods.md`, verbatim:

> "Maybe you've bound an unsupported key for 'Advanced Descriptions'. For example, APT cannot press mouse buttons."
> "Maybe you've non-ALT key bound for 'Advanced Descriptions' but the PoE configuration file is in an unusual location."

Y por eso APT **lee el fichero de configuración de PoE** para averiguar qué tecla es. Detalle menor para
el relato, relevante si alguien fuera a reimplementarlo.

## 🟡 E7 — `rank` no es "el rango del roll": son dos campos distintos

§0 dice que Ctrl+Alt+C devuelve "su *tier* y el rango del roll", y el resumen ejecutivo lo condensa como
"TIER y RANGO del roll". En `advanced-mod-desc.ts` son **dos campos separados y `rank` no significa eso**:

```ts
export interface ModifierInfo {
  type: ModifierType
  generation?: 'suffix' | 'prefix' | 'corrupted' | 'eldritch' | 'foulborn' | 'vestigial'
  name?: string
  tier?: number
  rank?: number      // ← NO es el rango min-max del roll
  tags: string[]
  rollIncr?: number
}
```

`rank` se rellena únicamente desde `ELDRITCH_MOD_R1` … `ELDRITCH_MOD_R6`: es el **rango jerárquico 1-6
de los mods eldritch** (Eater/Exarch), no el intervalo numérico del roll. El intervalo min-max sí aparece
en el texto avanzado, pero lo maneja otra parte del parser (`bounds.min` / `bounds.max` en
`stat-translations.ts`), no `rank`.

Lo demás del §0 sobre esta línea es correcto: **prefijo/sufijo (`generation`), nombre de mod (`name`) y
tier (`tier`) sí vienen regalados por el juego**, y eso es lo que sostiene el argumento.

## 🟢 E8 — `stashvision`: la pregunta abierta #10 ya se puede cerrar, y la tabla la tenía mal

La tabla del §1 le atribuye "API de stash + **visión sobre pestaña**", y "No encontrado" #10 deja
abierto si usa OCR. **He abierto el README y ya no hace falta dejarlo abierto:**

- La fuente de datos es **la API de stash de GGG autenticada con `POESESSID`**:
  `stashvision server -s=<poesessionid> -a=<account_name>`, y el fichero de config lleva
  `SessionId = xxx` con la nota "**SessionId** is your **POESESSID**".
- El componente visual es **un overlay en AutoHotkey que resalta la posición de los objetos**, y sólo
  funciona en "windowed borderless".
- **No hay OCR ni visión por computador**, pese al nombre. El README no menciona Tesseract ni OpenCV.

**Corrección propuesta para la tabla:** "API de stash (POESESSID) + overlay AHK que resalta posiciones.
Sin OCR." Y el punto #10 de "No encontrado" se puede eliminar.

## Notas menores (no son errores, para el corrector)

- **"~50 parsers"**: el array `parsers` tiene **58 entradas**, de las cuales unas **48 son funciones
  distintas** (hay duplicados deliberados: `parseModifiers` ×4 para enchant/scourge/implicit/explicit,
  `parseMercenaryGems` ×6, `parseLogbookArea` ×3). "~50" es una aproximación honesta; sólo conviene
  saber que los duplicados son intencionados y no un error de lectura.
- **Umbral de OCR**: §6.1 dice bien "descartando resultados con confianza ≤ 30"; §6.3 dice "tira todo lo
  que baje de 30", que es ligeramente distinto. El código es `confidence > 30`, o sea que **también tira
  el 30 exacto**. Vale la §6.1.
- **Las 2 reglas de encuadre** ("Both icons should be fully visible" / "The text should not be occluded
  by health bar or other elements") el informe se las atribuye a la guía de EE2; están **idénticas en la
  guía de APT** (`docs/ocr-guide.md`). El informe ya dice "y su gemela", así que es correcto, pero la
  fuente más directa es la de APT.
